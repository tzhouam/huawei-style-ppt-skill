# PPT Forge — 华为式专业汇报

## 先确定交付形态

- 用户要 **PPTX、Google Slides、可持续改稿**，或给了现有演示文稿时，优先保留其内容与风格，交付可编辑页面。文字、表格、图表、流程节点和连线用原生对象；真实截图、照片与视频可以作为媒体嵌入，但不能把整页做成一张图来冒充可编辑。
- 用户要独立图片或明确选择固定画面时，使用 raster PNG 路线。图片内文字须逐字复核，并说明不可独立编辑。
- 用户只要内容方案、或暂时缺少制作能力时，交付低保真 Markdown。不要把“能力不足”当成自动改变用户交付要求的理由；先使用宿主可用的原生工具。

开局记录受众、展示距离、时长、宽高比、既有模板、交付形态和内容取舍。可从材料推断的内容直接确定；只有会改变结论或无法继续的缺项才询问。用户已授权制作时，完成可审阅的成品与验证，不把分页确认设为每次必须停下的关卡。

## 内容先行

1. 读完材料、批注和现有页面，区分**原始证据、旧版叙述、待验证主张**。现有 deck 的最新用户修改与明确指令优先；沿用其视觉系统时，不复制过期数据。
2. 内部建立页序：每页一个清楚的主旨，标出事实、案例、图表、来源、运行边界与讲述时长。不要用统一的抽象词替代实际发生的事。
3. 对齐名称和责任：团队、产品、服务、执行 Agent、维护者分别写清，避免把组织名称误写成产品。流程箭头必须符合真实任务流；共享来源画成一个节点，再分别连接使用方。
4. 需要分页蓝图时，按[低保真制作规范](references/ppt-lofi-authoring.md)写区域比例和逐页文字清单；华为视觉均读取[风格 preset](references/ppt-style-huawei.md)。

## 原生可编辑路线

制作或修改 PPTX/Google Slides 时，读取[可编辑演示文稿与证据页](references/native-editable.md)。关键要求：

- 用原生形状、单段连接线、文本框和图表表达流程与数据；角色颜色、箭头、标签有明确语义。draw.io 风格应提升关系的可读性，不靠装饰堆出“科技感”。
- 真实案例用真实页面或终端截图，旁边写编号、发生的动作、可核验结果和限制。概念图、AI 生成图不能充当 GitHub 评审、运行记录或产品界面的证据。
- 一切数字说明时间窗、分母、状态时点和来源；不要把任务次数写成唯一 PR 数，也不要把观察差异写成因果改进。未合并、未运行或尚待人工验收的内容明确标注。
- 展示型文字用演示场景字号；放不下时先精简、重组或拆页，不依赖自动缩字。并列要点用项目符号，流程步骤用节点；图上不留“X 个”“待补充”等占位。
- 全稿渲染检查：封面、每页、并排缩略图、视频播放与可编辑性。检查遮挡、溢出、字体回退、截图清晰度、页码、链接颜色和图文一致性。可用仓库的 `scripts/check_pptx.py` 做结构预检，但不能代替目视检查。

## Raster 路线

先写低保真蓝图，锁定逐页文字、来源与宽高比，再使用可用的 imagegen 工具逐页出图；不一次生成整套拼图。生成后逐字核对中文、数字和单位。用户需要再编辑时，返回原生路线，而不是把 PNG 铺满每页。

## 华为式表达

华为风格是克制的红灰层级，不是满页红框。页面标题、关键数字、风险与结论可以用红色；正文通常黑或深灰，非重点不加粗。全宽红底结论条只在确有必要时使用，普通强调优先红字。保持同级模块的字体、留白、边界和图例一致；密度服从观看距离。

现有参考稿或用户指定的深红、浅蓝、边界签牌等细节优先于默认色板。科技流程页可采用风格 preset 的可选“AI／人工／知识”图式，但不要把一次项目中的组织、仓库、数字或案例写成通用模板。

## 交付检查

交付成品和必要的可核验来源，简述改动、验证与实际限制。若 Google Slides 与 PPTX 互相转换，分别打开检查文字、形状、媒体和链接；不能因为 PPTX 可编辑就推断导入后的 Slides 也完整可编辑。外部发布、写入和分享按用户已授予的范围执行。
